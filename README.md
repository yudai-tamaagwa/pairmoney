# pairmoney（ペアマニ） — React + Vite

スマホ・PC向け家計簿アプリの開発版。Reactの主要機能と初心者向け操作テストを実装しています。**金融機関API連携は未実装。Supabaseログイン・共有はコードを実装済みですが実接続と2端末同期は未検証**です。

## 起動

Node.js 20.19+ または 22.12+ を推奨。

```bash
npm install
npm run dev
```

表示されたURL（通常 http://localhost:5173）を開きます。停止はターミナルで Ctrl+C。

## 現在の機能

- 収支の集計、カテゴリー別の支出、明細登録・削除
- カード会社からエクスポートしたCSVの読み込み（UTF-8・Shift_JISなどを想定した処理、実ファイル検証は未完了）
- 店名キーワードに基づく分類、一致しなければ「その他」
- ほしい物リスト、貯金進捗、毎月の積立額による必要月数、購入賛成投票
- 生活費の割合による精算額試算
- JSONバックアップの書き出し
- ブラウザ内の localStorage に保存（同一端末・同一ブラウザのみ）

CSVヘッダー例：

```csv
日付,店名,金額,支払者,種別
2026-11-01,スーパー,3200,自分,支出
2026-11-02,給与,250000,自分,収入
```

「日付」「店名」「金額」は必須。UTF-8で保存してください。カード会社ごとに列名や文字コードが異なるため、必要に応じて変換してください。CSV重複チェックは簡易的なもので、同日・同店・同額の別決済を区別できません。

## 本番化の順序

1. Supabaseプロジェクト作成、Auth（メール認証等）を設定。
2. `supabase/schema.sql` をレビューして適用。世帯作成・招待の安全なサーバーAPIを実装。RLSをテスト。
3. localStorageの操作を認証済みSupabase APIに移行し、ふたりの端末で同期。
4. 金融データAPI事業者の法人・商用利用条件、日本の対応金融機関、審査・契約・費用を確認。
5. サーバー側でOAuth等の認可、トークンの暗号化保存、Webhook署名検証、定期同期、再試行、重複排除、連携解除を実装。**カードのログイン情報を自前で収集しない。**
6. 同期取引は `external_id` で冪等化。金額の符号・返金・取消・確定前明細・支払日を正規化し、分類ルールを適用。未知の店名は「その他」。
7. 共通費と個人費の区別、口座残高と目標貯金の二重計上防止、精算済み管理、テスト、バックアップ、監査ログを追加。

## セキュリティ

金融APIキーやrefresh token、Supabase service-roleキーを `VITE_` 変数やブラウザに入れないでください。`financial_connections` は参照メタデータのみ。秘密情報はサーバー側のシークレット管理に置きます。現時点では実際の金融情報を入力しないでください。

## v2: ふたりのログイン・共有（Supabase）

1. Supabaseでプロジェクトを作り、Authentication > Providers でEmailを有効にする。確認メールを使う場合はSite URLを公開URLに設定。
2. SQL Editorで `supabase/schema.sql` → `supabase/02_cloud_sync.sql` の順に実行する。
3. `.env.example` を `.env.local` にコピーし、SupabaseのProject URLと**公開用anon/publishable key**を入力する。`service_role`キーは絶対に入れない。
4. `npm install`、`npm run dev`。2人が別々のメールで新規登録し、一方がスペースを作成、もう一方が招待コードで参加。
5. Realtime更新を使う場合、Supabase DashboardのDatabase > Publicationsから `household_data` を `supabase_realtime` に追加する。

### 重要な制限

- **金融機関API連携は未実装**。現状はCSV取込・手入力のみ。金融データ提供事業者との契約とサーバー側のOAuth/トークン管理が必要。
- 同期は共有JSON文書をバージョン付きで保存する簡易実装。同時編集で競合すると保存エラーになります。競合時はデータのバックアップを取り、再読み込みしてやり直してください。本番運用には取引ごとのCRUD・競合解決・監査ログが必要です。
- 招待コードを知っている人は参加できます。共有しないでください。参加上限は2人です。コード再発行・退会機能は未実装。
- CSVのフォーマットはカード会社によって異なります。明細の自動重複判定は完全ではありません。
- 初回のローカル体験版データはクラウドに自動移行されません。クラウドの初期状態は空です。
- この段階はプロトタイプであり、金融機関の認証情報や本番の機微な家計データを投入する前に、セキュリティレビューを行ってください。

## v3: 汎用カード明細CSV取込
「明細」→「CSV取込」で、UTF-8/Shift_JIS の CSV または TSV を読み込みます。見出し行（先頭15行から選択）、日付・店舗・金額・支払者・種別の列を調整し、プレビュー確認後に保存できます。日付は YYYY/MM/DD、YYYY-MM-DD、YYYY年M月D日、YYYYMMDD に対応。ルールに一致しない店舗は「その他」です。同一の「日付・店舗名・金額・支払者・種別」は重複排除します（同日同店舗同額の別購入も重複扱いになる制限があります）。カード明細によっては分割払いや返金・支払額などの独自列があり、手動での確認が必要です。すべてのカード会社の形式を保証するものではありません。CSV原本はブラウザ内で解析し、取込確定後の取引情報のみ既存の保存先に登録します。クラウド共有利用時は登録した取引情報がSupabaseに送信されます。


## v4: CSV形式の保存とカテゴリー学習
- CSV取り込みプレビューで列の対応を設定し、名前を付けて保存できます。
- 次回同じヘッダー構成のCSVを読み込むと保存済み設定を自動適用します。
- 「明細」一覧のカテゴリーを変更できます。確認ダイアログで OK を選ぶと、同じ店舗名に対する分類ルールも保存します。キャンセルは今回の明細のみの変更です。
- 設定画面から保存済みCSV形式を削除できます。
- 既存の分類ルールとの優先順位は新しく学習した完全な店舗名のルールが先になります。既存明細は一括で書き換えません。
- カード会社名を自動特定するのではなく、CSVヘッダー構成で設定を照合します。形式変更時は再設定してください。
- 現在の重複判定は同日・同店舗・同金額の別取引を誤って除外する可能性があります。実運用前に明細固有IDなどを利用する改善が必要です。

## v4.1: CSVの安定化と自動テスト

- 同一CSV内の「同日・同店・同額」の複数決済を件数分保持する重複判定に変更。
- 同じCSVを再取込した場合は既存件数を超える分のみ追加。
- 不正な必須列指定を保存前にブロック。
- 分類キーワードが空の場合に全店舗に一致しないよう修正。
- `npm test` でCSVの解析・日付・金額・分類・重複判定の6テストを実行。

**制限:** 同じキーの取引が別のCSVファイルにまたがる場合、どの決済が同一か確定できません。完全な重複排除にはカード会社の取引IDや取込履歴の設計が必要です。CSVの金額が分割払いや返金を表す場合は取り込み前に確認してください。

**検証:** Node.js単体テスト6件成功。npm依存取得はこの環境からregistry.npmjs.orgへのDNS接続に失敗したため、Reactビルドとブラウザ動作は未検証。

## v4.2: 共有データ同期の安全対策
- 自分の保存成功によるバージョン更新では家計簿画面を再マウントしないよう修正しました（編集中フォームやタブの意図しない初期化を軽減）。
- 他端末からの変更は、未保存データがない場合のみ再読み込みします。
- 同期エラー・競合時は自動再送を停止し、未保存JSONを端末にダウンロードするボタンを表示します。再送を繰り返して他端末の変更を上書きしないための暫定措置です。
- 注意: 競合の自動マージ、再ログイン時の未保存復元、オフライン保存は未実装です。クラウドの実接続テストとRLSの検証はまだ必要です。
